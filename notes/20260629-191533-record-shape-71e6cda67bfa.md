## Reference Findings

- Records are nominal table types with a known set of string fields and field
  value types. The docs describe them as tables whose string keys are known in
  advance: `tl/docs/src/records.md:3-13`.
- `local record Point ... end` is shorthand for a local record type declaration:
  `tl/docs/src/records.md:26-35`, grammar at
  `tl/docs/src/grammar.md:31-44`.
- Record bodies may contain type parameters, `is` interface/array clauses,
  `where` clauses, field entries, metamethod entries, nested type entries,
  nested `record`/`enum` declarations, and string-literal keys:
  `tl/docs/src/grammar.md:117-125`.
- The first useful subset of record entries is `Name: type`, especially
  primitive fields and `function(...)` fields. Docs show `x: number`,
  `y: number`, and `draw: function(Obj)`:
  `tl/docs/src/records.md:31-34`, `tl/docs/src/records.md:90-99`.
- Record functions/methods may be declared after the record in the same scope
  with Lua dot/colon syntax: `tl/docs/src/records.md:69-88`.
- Nested records are used for module exports and dotted nominal references:
  `tl/docs/src/records.md:115-139`.
- Global records exist and are used for cross-file/circular type declarations:
  `tl/docs/src/global_variables.md:49-87`.
- Ordinary record literals may be partial, but extra literal fields are errors:
  `tl/spec/lang/assignment/to_nominal_record_spec.lua:37-58`.
- Record field assignment checks the declared field type and invalid literal or
  arbitrary string indexes are errors:
  `tl/spec/lang/assignment/to_nominal_record_field_spec.lua:15-49`.
- `self` inside record methods has the receiver record shape; assignments to
  `self.foo` must match the field type:
  `tl/spec/lang/assignment/to_self_record_field_spec.lua:3-22`.
- Unknown field reads are errors for inferred or nominal records:
  `tl/spec/lang/operator/dot_spec.lua:3-15`,
  `tl/spec/lang/operator/index_spec.lua:69-74`,
  `tl/spec/lang/declaration/record_spec.lua:258-328`.
- Duplicate non-function fields are rejected, but function fields may be
  overloaded in Teal proper:
  `tl/spec/lang/declaration/record_spec.lua:146-168`.
- `function R.foo` / `function R:foo` must only target concrete records, not
  interfaces/maps; specs also check signature consistency and redeclaration:
  `tl/spec/lang/declaration/record_function_spec.lua:3-50`,
  `tl/spec/lang/declaration/record_function_spec.lua:53-144`.

## Current TealJIT Hooks

- Current static Teal tags only track a coarse expression/local type plus nil:
  `src/lj_parse.c:68-89`.
- Current `local record` and `global record` only create a table and mark the
  slot as `TEAL_T_RECORD`, then skip the body:
  `src/lj_parse.c:2685-2720`.
- Dot/colon field parsing centralizes through `expr_field`:
  `src/lj_parse.c:2066-2075`.
- Assignment funnels through `parse_assignment` and `bcemit_store`:
  `src/lj_parse.c:2628-2668`, `src/lj_parse.c:650`.
- Function declarations parse dotted/colon names and then emit a field store:
  `src/lj_parse.c:2811-2829`.
- Strict returned-record freezing is already emitted for single returned record
  expressions: `src/lj_parse.c:1310-1328`,
  `src/lj_parse.c:2845-2863`, runtime helper at `src/lj_teal.c:23-60`.

## Minimal First Slice

1. Keep metadata parser-only and discard it before `GCproto` finalization. Do
   not add bytecode dump fields for shape metadata yet.
2. Represent each local/global record declaration by nominal identity plus an
   ordered set of fields: field name, field type, nilability, and whether it is
   a method/function field.
3. Parse `local record R ... end` and `global record R ... end` bodies for:
   `field: primitive-or-record-type`, `field: function(...)[: returns]`, and
   empty bodies. Keep existing runtime table emission.
4. Defer but gracefully skip or reject record body features outside the first
   slice: type parameters, `is`, `where`, nested records/enums/types,
   `metamethod`, string-literal keys, array/tuple record parts, `userdata`,
   macroexp fields, and overload sets.
5. Attach `function R.foo(...)` and `function R:foo(...)` to record `R` when
   `R` resolves to a known record in the current visible scope. For colon form,
   bind `self` to `R` while parsing the body.
6. For a declared function field, compare arity and primitive parameter/return
   tags against the declaration. For an undeclared `function R.foo`, add `foo`
   to the record shape while the record is still in its construction/open phase.
7. Check reads and writes when the base expression has a known record identity:
   `r.field` and `r["field"]` must name a declared field; `r[dynamic_string]`
   errors for now; writes must match the field type under current strict nil
   rules.
8. For table literals assigned to a record variable, allow missing fields but
   reject extra literal fields. Total-record checks can wait until `<total>` is
   fully implemented.
9. Freeze/open phase rule for the user's export pattern: allow adding fields to
   `local record export` until the record escapes by `return export`; after
   that, reject new fields statically in the same chunk and rely on the existing
   strict runtime freeze for Lua callers.

## First Errors To Implement

- Unknown record field read: `invalid key 'x' in record 'r'`.
- Unknown record field write/add after closed phase: `unknown field x`.
- Wrong field assignment type: `in assignment: got T, expected U`.
- Extra table literal key assigned to a record: `unknown field x`.
- Duplicate non-function field: `attempt to redeclare field 'x'`.
- `function R.foo` where `R` is not a concrete record: `record function syntax
  cannot be used with this type`.
- Function implementation does not match a declared function field: report
  arity/type mismatch.

## Risks

- Nominal identity is required; structural equality of two records with the same
  fields must still be rejected later:
  `tl/docs/src/records.md:44-58`,
  `tl/spec/lang/assignment/to_nominal_record_spec.lua:69-83`.
- Teal permits partial record literals, so strict frozen records need a
  shape-aware runtime path if nil-valued declared fields should remain writable
  after return.
- Current freeze helper preserves existing metatables and therefore does not
  freeze records that already have user metatables:
  `src/lj_teal.c:34-43`.
- Nested exported types (`module.Type`) are important for real Teal modules but
  require a shape/type namespace richer than the current local Teal tag arrays:
  `tl/spec/lang/declaration/local_type_spec.lua:10-34`.
- Record function overloads, generics, interfaces, enum-key indexing, and
  arrayrecords are common in specs but should be second-phase work to keep the
  first parser metadata implementation testable.
