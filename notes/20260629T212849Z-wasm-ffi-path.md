## Current Scaffold

- WASM64 enables `LJ_TARGET_WASM`, `LJ_TARGET_WASM64`, GC64, memory64 page
  assumptions, and does not set `LJ_ARCH_NOFFI` (`src/lj_arch.h`). The FFI C
  frontend is therefore compiled for the target, but `doc/wasm_vm.md` still
  documents the missing VM/backend gate for executing Lua code.
- `src/lj_wasm_host.h` declares host imports for FFI library load/unload,
  symbol lookup, call dispatch, and callback handle management. `LJWasmFFISig`
  exists, but the call path does not currently use it.
- `src/lj_wasm_host.c` is a thin guest wrapper around raw
  `lj_wasm_import_*` symbols. The Wasmtime C scaffold mirrors those symbols,
  validates nulls, delegates to installed hooks, and otherwise returns
  `LJ_WASM_HOST_NYI`.
- The Wasmtime scaffold currently treats `CTState *`, `CType *`, and
  `CCallState *` as opaque pointers. A real Wasmtime linker must treat them as
  WASM64 guest-memory offsets and bounds-check/decode them before reading or
  writing call state.

## LuaJIT FFI Flow

- Library path: `ffi.load()` calls `lj_clib_load()`, which routes WASM loads
  through `lj_wasm_host_ffi_load()`. Library indexing resolves symbols through
  `lj_wasm_host_ffi_symbol()` and stores the returned host handle in a function
  cdata pointer slot.
- Default namespace caveat: `ffi.C` is created by `lj_clib_default()` with
  `CLIB_DEFHANDLE == NULL` on WASM, while the Wasmtime contract test currently
  expects `ffi_symbol(NULL, ...)` to fail. The first working smoke should use an
  explicit `ffi.load(...)`, or the default namespace needs a real host-owned
  default handle.
- Call path: `lj_ccall_func()` extracts the cdata function handle, calls
  `ccall_set_args()`, and for WASM calls `lj_wasm_host_ffi_call(cts, ct, &cc)`
  instead of `lj_vm_ffi_call(&cc)`. After the host returns, `ccall_get_results()`
  converts `cc.gpr`/`cc.fpr`/retref state back to Lua values.
- WASM call layout currently reuses a LuaJIT ABI-like `CCallState`: up to eight
  GPR args, eight FPR args, stack slots, `ngpr`, `nfpr`, `nsp`, and retref.
  Struct returns are forced through an explicit return pointer; struct args are
  copied to temporary cdata and passed by pointer. This is workable for a host
  call shim, but not yet a stable cross-runtime descriptor.
- Callback creation path: converting a Lua function to a C function pointer
  calls `lj_ccallback_new()`. On WASM, callback slots do not allocate native
  executable stubs; `callback_slot2ptr()` asks the host for a callback handle.
  `cb:set()`/`cb:free()` can resolve and free the handle through host imports.
- Callback entry is not implemented by the scaffold. Native backends jump
  through `lj_vm_ffi_callback`, populate `cts->cb.slot`, `cts->cb.gpr/fpr/stack`,
  call `lj_ccallback_enter()`, run the Lua function, then call
  `lj_ccallback_leave()` to write the result. A WASM host/table trampoline still
  has to provide that state and re-enter the guest VM.

## Smallest Next Slice

Implement scalar explicit-library calls before callbacks:

1. Keep the current LuaJIT guest call path: `ffi.load()` -> symbol handle cdata
   -> `ccall_set_args()` -> `lj_wasm_host_ffi_call()` -> `ccall_get_results()`.
2. Define and test a narrow "FFI v0" subset: non-vararg calls with only
   `void`, 32/64-bit integers, `float`, `double`, and pointer-sized handles;
   no aggregates, complex numbers, long double, default `ffi.C`, or callbacks.
3. Make `LJWasmFFISig` real or add a small adjacent call-frame descriptor that
   records result type, fixed arg count, per-arg scalar type, and each value's
   location in `CCallState`. This lets the Wasmtime host avoid reverse-engineering
   arbitrary `CType` chains for the first working call.
4. Add host-side coverage that a hook decodes a synthetic scalar `CCallState`,
   invokes a known native function, writes the result back, and reports NYI for
   unsupported signatures. Then use the same path for the eventual Lua smoke,
   e.g. explicit `ffi.load("m").cos(0.0)` or a tiny host test library function.
5. Defer callback invocation until after scalar calls work. The callback slice
   should add an explicit host-to-guest trampoline contract that sets
   `cts->cb.slot`, argument arrays, and stack pointer, calls
   `lj_ccallback_enter/leave`, and maps traps/errors back to host status.

This moves the path from contract-only stubs to a real, testable FFI crossing
without forcing the host to solve default namespaces, aggregate ABI lowering, or
Lua callback re-entry in the same step.
