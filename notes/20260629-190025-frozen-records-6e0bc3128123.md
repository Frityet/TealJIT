# Frozen record enforcement path

Date: 2026-06-29T19:00:25Z
Commit: 6e0bc3128123

Scope: no source edits. Inspected current native Teal scaffold plus LuaJIT
table/metatable/bytecode/JIT integration points for strict-mode frozen record
exports from `.tl` files.

## Current scaffold

- `.tl` source detection happens at load time in `src/lj_load.c:51-52`.
- `lj_teal_parse()` only flips lexer mode and strict defaults, then calls the
  ordinary parser in `src/lj_teal.c:46-50`.
- Teal mode and strict state live only in `LexState` (`src/lj_lex.h:51-80`);
  source chunks compile to normal `GCproto *`.
- The parser currently tracks only coarse Teal types on expressions and locals:
  `ExpDesc.teal_type/teal_nil` at `src/lj_parse.c:55-70`, primitive
  `TealType` at `src/lj_parse.c:72-86`, and per-local arrays in
  `FuncState` at `src/lj_parse.c:142-170`.
- Local record declarations currently materialize an ordinary table with
  `BC_TNEW` and mark the local as `TEAL_T_RECORD` in
  `src/lj_parse.c:2491-2505`. Global record declarations similarly emit
  `BC_TNEW` plus `GSET` in `src/lj_parse.c:2508-2525`.
- Function field assignment such as `function export.add(...)` goes through
  normal indexed-store bytecode emission in `src/lj_parse.c:2618-2634` and
  `src/lj_parse.c:665-687`.
- Return checking currently only checks the last returned expression's coarse
  static type in `src/lj_parse.c:2650-2667`; it does not freeze records or
  preserve record shape metadata.

## Table and metatable mutation points

- `GCtab` has `nomm`, `colo`, `array`, `metatable`, `node`, `asize`, and
  `hmask`, but no obvious spare frozen bit (`src/lj_obj.h:498-511`). `nomm` is
  the negative metamethod cache; `colo` is array-colocation state.
- Table allocation initializes `nomm`, `colo`, `metatable`, array/hash state in
  `src/lj_tab.c:80-126`; duplicating template tables copies layout in
  `src/lj_tab.c:163-202`.
- New key insertion funnels through `lj_tab_newkey()` at
  `src/lj_tab.c:435-509`; setters call that from `lj_tab_setinth()`,
  `lj_tab_setstr()`, and `lj_tab_set()` at `src/lj_tab.c:511-560`.
- `lj_meta_tset()` implements the generic `__newindex` path and only creates a
  new key when the previous value is nil and no `__newindex` exists
  (`src/lj_meta.c:160-198`).
- The x64 interpreter fast paths for `TSETV`, `TSETS`, and `TSETB` also check
  `__newindex` when the previous value is nil before creating/writing a new
  key (`src/vm_x64.dasc:3875-3988`, `src/vm_x64.dasc:3990-4019`).
- The recorder mirrors this contract: table stores call `lj_record_idx()` from
  `src/lj_record.c:2555-2579`; `lj_record_idx()` checks prior value and
  `MM_newindex`, then emits `IR_NEWREF` only for a true new key in
  `src/lj_record.c:1530-1675`. `IR_NEWREF` is defined at
  `src/lj_ir.h:88-95` and backed by `lj_tab_newkey` in
  `src/lj_ircall.h:185-190`.
- Public `setmetatable` only rejects protected metatables via `__metatable`,
  then writes `t->metatable` directly in `src/lib_base.c:131-140`.

## Conservative implementation path

1. Add parser-only record shape metadata, not bytecode metadata.
   Track a compact native shape for record locals in `FuncState`, parallel to
   `teal_vtype`, containing the declared field names/types and whether a record
   local is still in its construction phase. This state must be discarded before
   `GCproto` finalization so bytecode dumps remain normal LuaJIT 2.1 bytecode.

2. Enforce no-new-fields at compile time for `.tl` code first.
   When parsing `record R ... end`, collect declared fields instead of only
   skipping the body. When an indexed assignment targets a statically-known
   record local through dot syntax, reject unknown fields in strict mode before
   `bcemit_store()`. The natural hooks are field parsing around
   `src/lj_parse.c:1885-1893`, assignment around `src/lj_parse.c:2435-2467`,
   and function declaration stores around `src/lj_parse.c:2618-2634`.

3. Treat the user's namespace pattern as a construction exception.
   For:

   ```
   local record export end
   function export.add(a: integer, b: integer): integer
     return a + b
   end
   return export
   ```

   the declaration has no fields, but subsequent `export.add = <function>` is a
   valid module-construction write. A practical strict rule is: local concrete
   record tables are extensible only within their defining `.tl` chunk/function
   until they escape through `return`/assignment to an outer/global. At escape,
   freeze the runtime table shape. Later `.tl` writes to fields outside the
   collected construction shape are compile-time errors.

4. Add runtime freezing through ordinary metatables as the first cross-language
   enforcement mechanism.
   Emit a call to a small C helper, e.g. `lj_teal_freeze_record(L, table)`, just
   before returning a strict-mode record from a top-level `.tl` chunk. The helper
   should install a protected metatable whose `__newindex` raises a TealJIT
   error, and whose `__metatable` prevents plain `setmetatable` replacement.
   This uses existing VM semantics: updates to existing non-nil fields remain
   allowed; creating a missing field routes through `__newindex`.

5. Preserve LuaJIT 2.1 bytecode compatibility by avoiding new opcodes and dump
   fields for this milestone.
   The dump format is versioned in `src/lj_bcdump.h:31-47`; the comment at
   `src/lj_bcdump.h:36-39` warns that private bytecode/dump modifications must
   bump the version. Freezing implemented as normal calls plus metatables leaves
   `BC_TNEW`, `BC_TSET*`, `BC_RET*`, and bytecode reading/writing unchanged.

6. Do not change `GCtab` layout yet.
   Adding a frozen flag to `GCtab` would require VM fast-path checks in every
   architecture-specific `vm_*.dasc`, JIT recorder guards, snapshot/sink safety
   review, and ABI/layout review. It may be faster later, but it is not the
   compatibility-preserving first step.

## Risks

- A metatable freeze only blocks writes to fields whose current value is nil or
  absent. This matches "no new fields", but it does not make existing fields
  immutable.
- If a declared field exists in the shape but is currently nil, ordinary Lua
  table semantics would route assignment through `__newindex`; to allow typed
  nilable fields while still rejecting unknown fields, the freeze metatable may
  need a shape side table and a C `__newindex` helper that raw-sets known keys.
- Installing a metatable may conflict with records that intentionally use a
  user metatable/metatable<T>. The first milestone should either reject freezing
  those records or chain/merge very carefully.
- The JIT recorder must either see an ordinary `__newindex` function call or be
  taught about the freeze helper. A plain Lua/C metamethod path should be
  correct but may not be the fastest path yet.
- Table constructors and aliases need separate shape propagation. Current
  parser metadata only knows `TEAL_T_RECORD`, so nominal identity and field
  shape are not available for expressions yet.
- Top-level `.tl` export detection is compile-time only; runtime values can
  flow through closures/upvalues. Freezing on `return` is a good module-boundary
  start, not a complete escape analysis.

## Tests to add

- Positive: strict `.tl` module can build `local record export end`, define
  `export.add`, return it, and Lua caller can call `add`.
- Runtime negative: after `local m = dofile("mod.tl")`, `m.extra = 1` raises a
  TealJIT frozen-record error.
- Runtime positive: assigning an existing exported field, if intended by the
  strict semantics, either works (`m.add = m.add`) or produces the documented
  stricter error if fields become immutable later.
- Compile-time negative: strict `.tl` write to `export.missing` after the
  construction/freeze point fails.
- Strict-off: `-t strict=off` and `--#pragma strict off` skip freeze emission.
- Bytecode compatibility: `luajit -b mod.tl mod.ljbc` and loading old LuaJIT
  2.1 bytecode still work without version changes.
- JIT: hot loop attempting `m.extra = i` exits through/metamethod-errors
  consistently with interpreter behavior.
