# 20260629-213134 union type slice

Base commit: 46de37a0f2e65a1779fca22fd2e44492d57c2496

Scope:
- Added native union type descriptors owned by `FuncState`.
- Parsed `A | B` into normalized union descriptors, flattening nested unions and collapsing covered members such as `integer | number` to `number`.
- Kept strict nil semantics for this fork: unions that include `nil` carry nilability, but nil-bearing values are still not assignable to non-nil destinations without narrowing.
- Implemented union assignment compatibility: values assign to a union when any arm accepts them; union sources assign to a destination only when every arm is accepted.
- Rejected `any` sources assigned directly into narrower unions.
- Added runtime-discriminability guards for native union arms we can currently represent, including multiple table/record-like, function, or userdata arms.
- Generated unions for variable integer indexing over tuple table types, so `{string, integer}` indexed by an integer variable yields `string | integer`.
- Kept tuple declarations and heterogeneous list literal metadata permissive so invalid generated unions fail at the variable-index operation, matching Teal's tuple semantics.

- Dirac (019f1542-40d1-7042-a1d8-3eace4821d80) checked upstream Teal union parsing, assignment compatibility, nil/any/unknown behavior, normalization, invalid runtime-discriminability cases, and tuple variable indexing semantics.

Known follow-ups:
- Native union validation does not yet model Teal's full discriminator machinery for `where` or `__is`.
- Record type descriptors still do not carry distinct record identities, so unions of two different records cannot be diagnosed as precisely as upstream yet.
- Unannotated heterogeneous table literals still are not fully inferred as tuple tables; this slice only avoids premature invalid-union errors for those literals.
- Diagnostics are still TealJIT-native and not word-for-word upstream Teal diagnostics.
