Subject: Simple parser-owned Teal type aliases

Implemented a first native type-alias pass in `src/lj_parse.c`.

What changed:
- `FuncState` now carries parser-only type alias metadata:
  alias name plus expanded `TealTypeDesc`.
- `FuncScope` records the active alias count so aliases roll back at block
  scope exit.
- The Teal type-name resolver now checks builtins first, then active aliases,
  then falls back to the existing nominal-record placeholder behavior.
- `local type Name = ...`, bare `type Name = ...`, and `global type Name = ...`
  now parse without emitting bytecode.
- Aliases expand structurally to the scalar type metadata the checker already
  understands, including strict nilability and parser-owned function
  signatures.
- Duplicate aliases in the same block and aliases shadowing primitive builtins
  are rejected.

Covered in `test/tealjit`:
- `type_aliases.tl` exercises primitive, nilable, and function aliases in local
  annotations, function params, record fields, callback calls, and block-local
  alias shadowing.
- `type_alias_primitive_bad.tl` rejects a bad primitive alias assignment.
- `type_alias_nil_bad.tl` rejects assigning `Count | nil` to `Count` under
  strict nil safety.
- `type_alias_function_call_bad.tl` rejects a bad call through an aliased
  function type.
- `type_alias_param_bad.tl` rejects a bad direct function argument through an
  aliased parameter type.
- `type_alias_function_assign_bad.tl` rejects an incompatible function assigned
  to an aliased callback type.
- `type_alias_record_field_bad.tl` rejects a bad assignment to a record field
  typed through an alias.
- `type_alias_duplicate_bad.tl` rejects duplicate aliases in one block.
- `type_alias_builtin_bad.tl` rejects aliasing over a primitive builtin name.

Harvey's read-only scout matched this shape and called out that this is a
structural expansion slice, not full Teal nominal alias/interface semantics.

Known follow-ups:
- Generic aliases are rejected for now.
- Record/interface/enum aliases still collapse to the existing record
  placeholder behavior.
- Cross-module alias exports/imports, declaration files, and full nominal
  identity remain future type-system work.
