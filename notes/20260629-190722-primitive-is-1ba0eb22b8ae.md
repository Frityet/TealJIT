Subject: Native parser support for Teal primitive `is`

Implemented the first integrated Teal `is` operator slice in `src/lj_parse.c`.
The parser now recognizes `is` as a Teal-only soft binary operator at comparison
precedence and accepts primitive type RHS forms through the existing Teal type
parser. It enforces the Teal grammar restriction that `is` tests variables, not
arbitrary expressions.

Code generation remains LuaJIT 2.1 bytecode compatible for this checkpoint:
no opcode numbers or bytecode dump fields were changed. The lowering folds
obvious static results, uses existing equality bytecode for nil/non-nil tests,
and emits `type(x) == "<kind>"` plus a modulo integral check for runtime
integer discrimination. Russell's note documents the proper later native opcode
path: append a predicate bytecode instead of reusing `BC_ISTYPE`/`BC_ISNUM`,
because those are throwing/coercing library argument guards.

Also fixed two strict-type correctness issues exposed by the new tests:
- bare type `nil` now parses as `TEAL_T_NIL`, not unknown nilable;
- integral numeric literals infer as `integer` even when LuaJIT is built without
  dual-number TValue tags.
