# 20260629-220619 strict nil refinement slice

Base commit: 0d0a538891271cc3b46049eef7f5297b081ce3c1

Scope:
- Added native static result typing for global `assert(...)` calls.
- In strict TealJIT mode, `assert(x)` now returns the first argument with nilability removed, matching the fork requirement that `assert` can refine `T | nil` to `T`.
- Added conservative static result typing for `or` expressions.
- `x or fallback` now keeps the truthy left type when possible and includes the fallback type only when the left side may be falsy.
- Tightened previously unsound cases where `assert(string)` or `string | nil or integer` could satisfy an `integer` annotation through unknown call/result typing.

Reference agent:
- Lovelace (019f1565-f7c4-74c3-939b-a71114869b69) checked upstream Teal `assert`, `or`, and `and` semantics. Upstream `assert` is fact/truthiness based rather than return-type nil removal, but this fork intentionally uses `assert` as a strict nil-safety escape hatch per the project goal.

Known follow-ups:
- `and` expressions do not yet propagate facts into the right-hand expression the way upstream Teal does.
- `or` result typing is intentionally conservative and does not yet use an expected destination type to choose an explicit union.
- Builtin handling is currently limited to global `assert`, not shadowing-aware standard library declarations.
