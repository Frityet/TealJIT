Subject: Parser-only function signature and call checks

Implemented the first fixed-position function signature metadata pass in
`src/lj_parse.c`. This is parser/checker metadata only and does not alter the
LuaJIT bytecode format.

What changed:
- `ExpDesc` now carries a static Teal function signature id.
- `FuncState` now owns parser-only signature tables, parameter type/nilability
  arrays, and local/record-field signature ids.
- Signature-bearing expressions, locals, and record fields also retain the
  `FuncState` that owns the signature table, so nested functions can check calls
  through enclosing-scope function values without id collisions.
- `parse_params()` records typed parameters and optional markers.
- `parse_body()` builds a parent-visible signature after the child function is
  parsed, including single return type and nilability.
- Local functions and inferred local function values retain signature ids.
- Open record function fields such as `function export.mul(...)` retain their
  function signatures, so later calls through `export.mul(...)` can be checked.
- Calls to known signatures now check strict arity and positional argument
  assignability, and call expressions inherit the annotated single return type.

Covered in `test/tealjit`:
- `function_calls.tl` exercises local functions, optional parameters, return
  propagation, and open-record function calls.
- `function_call_arity_bad.tl` rejects missing required arguments.
- `function_call_type_bad.tl` rejects bad positional argument types.
- `function_call_upvalue_type_bad.tl` rejects bad argument types when a nested
  function calls an enclosing typed function.
- `function_call_return_bad.tl` verifies annotated return type propagation.
- `record_function_call_type_bad.tl` rejects bad argument types through a record
  function field.

Known follow-ups:
- Function type declarations like `field: function(string): integer` are still
  parsed only coarsely as `function`.
- Method `self` shape/signature handling, colon-call implicit receivers,
  varargs, tuple/multi-return values, overloads, generic functions, function
  subtyping, and `--#pragma arity off` remain to be implemented.
